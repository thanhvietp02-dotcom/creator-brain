# 发布与复盘

目标：每一条发出去的内容都留下数据和一句结论，攒多了就是用户自己的爆款规律。

## 一、发布登记

用户说"发了"时：

1. 问链接（或标题 + 平台 + 发布日期）。
2. 选题卡状态改成"已发布"，写上链接和发布日期。
3. 在 `07.发布与复盘/发布记录.csv` 追加一行（数据先空着），`记录日期` 写今天，`发布后天数` 写 0。
4. 提醒用户：3 天后、7 天后各来记一次数据。如果 AI 工具支持定时提醒，问用户要不要设。

## 二、记数据（第 3 天、第 7 天）

和对标一样，用户不碰表格，三种方式任选：

- 给链接：AI 打开视频页读点赞、评论、收藏；
- 发截图：请用户截创作者中心这条视频的数据页（播放、完播率、涨粉在这里才看得到）；
- 直接说："这条 3 天 2 万播放，800 赞，涨了 60 个粉。"

每次在 `发布记录.csv` 追加一行新的快照（不改旧行）。表头固定为：

```
发布日期,平台,标题,选题类型,形式,链接,记录日期,发布后天数,播放,点赞,收藏,评论,分享,涨粉,备注
```

数字列只写数字；不知道的留空。记完复述："记下了：发布 3 天，800 赞，是你平时一条的 2.4 倍。"

## 三、算"是平时的几倍"

```bash
python scripts/retro.py --root "<知识库>"
```

生成 `07.发布与复盘/复盘_<日期>.md`：

- 你平时一条大约多少赞（所有已发布作品最新一次记录的中位数）；
- 每条是平时的几倍；
- 按选题类型、形式分组，哪类平均倍数最高。

发布不足 5 条时，倍数参考意义有限，如实告诉用户。

## 四、写一句结论

对每条第 7 天的数据，和用户一起回答三个问题，写进 `07.发布与复盘/<标题>.md`：

1. 是平时的几倍？（数据）
2. 为什么？（用户的判断：选题、开头、时机、封面……AI 可以提供对比，但结论由用户说）
3. 下次怎么做？（一句可执行的话）

当同一种原因出现 2 次以上（比如"结果先行的开头，两次都是平时 3 倍以上"），提议把它写进 `09.我的方法论/我的爆款规则.md`，格式：

```markdown
- <规则一句话>（依据：<标题1> 3.2 倍，<标题2> 4.1 倍；<日期>）
```

规则被新数据推翻时，不删，改成"~~原规则~~ → 新结论（依据）"。
