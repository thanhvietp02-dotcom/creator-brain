# 选题

原则：先用数据证明"这类选题别人反复做爆过"，再考虑"我能不能做、我做有什么不一样"。

## 一、找"反复验证过"的选题

先确保对标数据够用（至少 5 个号、最近 45 天有作品），然后跑：

```bash
python scripts/viral_score.py --root "<知识库>" --days 45
```

报告里"选题验证"一节按选题类型列出：

| 列 | 意思 |
|---|---|
| 爆款条数 | 这类选题里达到爆款标准的作品数 |
| 做爆的号数 | 有几个不同的号做爆过。**最重要**：越多越说明不是偶然 |
| 小号也爆 | 其中粉丝 < 5 万的号做爆的条数。多，说明新号也能靠它起来 |
| 最近一次 | 最近一条爆款的日期。越近越好 |
| 收藏/点赞 | 中位数，≥0.7 是教程型 |

推荐给用户的选题，至少满足：**做爆的号数 ≥ 4、最近一次在 30 天内**。不满足就如实说"样本不够，先多加几个对标号"。

选题类型是按标题关键词分的，规则在知识库的 `system/选题分类.json`，可以改：

```json
{"新工具上手教程": ["零基础", "保姆级", "速通", "入门"], "清单推荐": ["必装", "神器", "N个"]}
```

用户的领域和默认分类差别大时（比如做美食、做母婴），先和用户一起把分类改成他领域的说法，再跑。

## 二、把选题落到"我能做"

对每个推荐的选题类型，给用户：

1. 2～3 条代表作：账号、标题、点赞、平时的几倍、链接。
2. 一个具体题目示例，结合用户的身份（`01.账号定位/账号定位.md`）。
3. 和对标的区别：用户的经历能讲出什么别人讲不了的。说不出区别的选题，排后面。

## 三、选题卡

用户认可的选题，写进 `05.选题池/<题目>.md`：

```markdown
# <题目>

- 状态：想法 | 待写 | 写作中 | 已拍 | 已发布 | 放弃
- 形式：短视频（约 2 分钟）| 深度教程 | 图文
- 选题类型：<和 system/选题分类.json 一致>
- 依据：<几个号做爆过、代表作链接、日期>
- 我的角度：<用户能讲出的不一样>
- 开头一句：<草稿>
- 引流钩子：<送什么、怎么领，见 private-traffic.md>
- 创建：<日期>
```

`05.选题池/_索引.md` 一行一个选题：状态｜题目｜依据强度（号数）｜创建日期。用户问"下一条拍什么"时，按"依据强度高、最近一次爆款近、用户角度清楚"排序，推荐前 3 个。

## 四、时机

- 新工具、新功能刚火的头几周，"零基础教程"类选题最容易爆。用户提到某个新东西时，先查对标库里最近有没有人做、做得怎么样。
- 同一个工具的续集（进阶篇、高级篇）通常远不如第一篇，提醒用户。
