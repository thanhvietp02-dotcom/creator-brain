# 搭建知识库

## 1. 确定放在哪

- 用户给了路径：用它（转成绝对路径）。
- 用户说"就这个文件夹"，而当前目录边界清楚（不是主目录、磁盘根目录、下载目录）：用当前目录。
- 都没有：问一句"知识库放在哪个文件夹？比如 D:\我的自媒体"，等回答。

## 2. 了解用户（最多问 5 个问题，已经知道的不问）

1. 主做哪个平台？（抖音 / 小红书 / 视频号 / B站 / 公众号，可多选）
2. 账号想做什么方向、给谁看？一句话就行。
3. 你是谁：职业、经历里最能让人信你的一点。
4. 想做什么形式？（比如 2 分钟口播、深度教程、图文）
5. 有没有已经很喜欢的对标账号？给链接或名字。

答案写进 `01.账号定位/账号定位.md` 和 `system/关于我.md`。用户说"先跳过"就留空，以后再补。

## 3. 预览再建

```bash
python scripts/init_vault.py --root "<知识库路径>" --name "<账号名>"
```

把预览结果用人话告诉用户："会新建 12 个文件夹、20 个说明文件，你原来的 N 个文件不动。"用户同意后：

```bash
python scripts/init_vault.py --root "<知识库路径>" --name "<账号名>" --apply
```

## 4. 接管已有文件夹

文件夹里已经有资料时：

1. 先只读看根目录和一两层子目录，不要一上来读全部正文。
2. 告诉用户你看到了哪几类资料（比如"脚本草稿 30 份、截图 200 张、录音 5 个"）。
3. 照样跑 `init_vault.py`：它只补缺的目录和说明文件，不碰已有文件。
4. 已有资料**不搬家**。在 `INDEX.md` 的"已有资料"一节写清楚：什么资料、在哪个文件夹、以后归到哪个模块用。
5. 用户同意后，才可以把明显该归位的文件移动到新目录，移动前列清单。

## 5. 建完之后

- 用 3～5 句话告诉用户：知识库在哪、每个文件夹放什么、下一步建议做什么（通常是"给我 2～3 个对标号的链接"）。
- 在 `system/日志.md` 记一笔。
- 推荐用户用 Obsidian 打开这个文件夹看，但不是必须。
