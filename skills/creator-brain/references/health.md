# 健康检查

知识库用久了会乱：链接失效、笔记没人连、收件箱越堆越多、出现好几个"最终版"。定期检查，问题早发现。

## 跑检查（只读，不改任何文件）

```bash
python scripts/health_check.py --root "<知识库>"
```

检查项：

| 检查 | 说明 |
|---|---|
| 入口文件 | `AGENTS.md`、`INDEX.md`、`本周.md`、`system/日志.md` 是否存在 |
| 断链 | `[[笔记]]` 和 `[文字](相对路径)` 指向的文件是否存在 |
| 孤立笔记 | 没有被任何笔记或索引提到的笔记（`_索引.md`、README、模板除外） |
| 收件箱积压 | `00.收件箱/` 里超过 7 天没处理的文件 |
| 重复终稿 | 同一目录里文件名带"最终""final""终版"的有 2 个以上 |
| 疑似敏感文件 | `.env`、`*.pem`、`*.key`、带 cookie/token/password 字样的文件名（只报路径，不读内容） |
| 数据文件 | `作品.csv`、`发布记录.csv` 表头是否正确，有多少行读不出数字 |

加 `--save-state` 会把结果存到 `system/健康状态.json`，下次可以对比。

## 告诉用户

先说总体："整体健康 / 有 3 个问题需要处理"。然后每个问题写：在哪 → 什么问题 → 可能的影响 → 建议怎么改。

## 修复

- 修复要逐项问用户，用户同意哪项改哪项。
- 不删除文件；需要"删"的，移到 `_旧版/` 或 `00.收件箱/待删/`，让用户自己删。
- 改完在 `system/日志.md` 记一笔，再跑一次检查确认。

建议每周跑一次，或者批量接入资料、调整目录之后跑一次。
