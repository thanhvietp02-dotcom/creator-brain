# 对标

目标：找到几个"和用户情况接近、最近涨得快"的号，用数据看清它们哪些内容真的火了，而不是凭感觉。

## 一、用户不碰表格

数据由 AI 收集、AI 记录。用户只需要做下面三件事中的一件，按顺序尝试：

### 方式 1：给链接（首选）

用户发主页链接或视频链接。如果你有浏览器能力（例如 Codex 的 Chrome 插件、Claude in Chrome、内置浏览器），并且用户允许：

1. 打开主页，读：账号名、粉丝数、作品数、简介。
2. 往下滚动，读作品列表里每条的标题、点赞数、是否置顶；能看到发布时间、收藏、评论就一起读。读到 20～30 条即可，不需要全部。
3. 点赞最高的 3 条可以点进去，读收藏、评论数和发布时间。
4. 一个号看完停几秒再看下一个；遇到验证码或登录弹窗就停下，请用户处理。

没有浏览器能力，或页面打不开：转方式 2。

### 方式 2：发截图

请用户截这几张图（手机或电脑都行）：

- 主页顶部（粉丝数、简介）；
- 作品列表，往下滑多截几屏（能看到每条的点赞数）；
- 想细看的那几条视频的详情页（发布时间、收藏、评论）。

从图里读数。图里看不清的数字留空，标"待确认"。

### 方式 3：直接说

用户说"他那条讲 Codex 的有 5 万赞"，就记一条，来源写"口述"。

### 记完要复述

每次记完，用一句人话复述，请用户确认：

> 记下了「XX」：粉丝 3.2 万，看了 24 条作品，平时一条大约 800 赞。最火的是「YYY」1.6 万赞，是他平时的 20 倍。数字有不对的告诉我。

## 二、数据存在哪（给 AI 看的，不要让用户打开）

`02.对标库/数据/作品.csv`，UTF-8 带 BOM，一行一条作品。表头固定为：

```
平台,账号,账号链接,粉丝,作品标题,发布日期,点赞,收藏,评论,分享,是否置顶,作品链接,记录日期,数据来源
```

- `发布日期`：`YYYY-MM-DD`；只知道"3 天前""10-05"这种时，按记录日期换算成完整日期；完全不知道留空。
- 数字列只写数字："1.2万"写成 `12000`，"10w+"写成 `100000` 并在 `数据来源` 里注明"约数"。
- `是否置顶`：`是` / `否`。置顶作品通常是爆款，算"平时一条"时会被排除。
- `数据来源`：`链接` / `截图` / `口述`。
- 同一条作品再次记录时，**追加新的一行**（记录日期不同），不要改旧行。脚本会自动取最新一次。

## 三、每个号一张账号卡

`02.对标库/账号/<账号名>.md`：

```markdown
# <账号名>（<平台>，<粉丝> 粉，记录于 <日期>）

- 主页：<链接>
- 他是谁：<简介里的身份、背书>
- 做什么：<一句话>
- 什么形式：<真人口播 / 录屏教程 / 图文……>
- 平时一条：约 <中位数> 赞（看了 <N> 条）
- 爆过的：<标题>｜<点赞>｜平时的 <倍数> 倍（每条一行，最多 5 条）
- 怎么变现 / 引流：<简介、置顶、评论区里看到的>
- 我能学的：<用户的判断>
- 我不学的：<用户的判断>
- 标记：重点对标 | 内容参考 | 形式参考 | 商业模式参考 | 不做
```

"我能学的 / 不学的 / 标记"由用户说，AI 不要替用户下结论；用户还没表态就写"待看"。

## 四、算倍数

数据记了 3 个号以上时，跑：

```bash
python scripts/viral_score.py --root "<知识库>" --days 45
```

它会生成 `02.对标库/选题验证_<日期>.md`。怎么读，告诉用户这几点：

- **爆款倍数** = 这条的点赞 ÷ 这个号平时一条的点赞（平时一条 = 非置顶作品点赞的中位数）。大号随便一条都几万赞，看倍数才知道是不是选题本身起了作用。
- 一个号少于 8 条作品时算不准，报告里不给它算倍数。
- 默认"爆款"= 平时的 5 倍以上，且点赞 ≥ 3000（门槛可用 `--mult`、`--min-likes` 调；号普遍很小时把点赞门槛调低）。
- **收藏/点赞**高（≥0.7）说明是教程型，看的人想照着做，最容易转成粉丝；低（<0.3）多半是看热闹。

## 五、怎么找新对标

- 让用户在平台里搜 3～5 个和自己方向相关的词，把前排的号链接发给你，或截图。
- 优先看：粉丝 1 万～50 万、最近 3 个月内有过平时 5 倍以上爆款、形式用户能做到的号。
- 用户自己关注的号里，常常就有最合适的对标。
